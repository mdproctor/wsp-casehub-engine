# engine#221 + engine#229 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `MessageType` to `CaseChannelProvider.postToChannel()` (engine#221) and add `triggerChannelId`/`triggerCorrelationId` to `ProvisionContext` (engine#229) as two independent, separately-committed PRs.

**Architecture:** Track A (engine#221) promotes the 3-arg `postToChannel` to a 4-arg abstract method that takes a `MessageType` from `casehub-qhorus-api`, adds a backward-compatible 3-arg default that delegates with `null`, and updates the one call site in `WorkerScheduleEventHandler` to pass `MessageType.COMMAND` explicitly. Track B (engine#229) adds two nullable `String` fields to the `ProvisionContext` record, updates all construction sites to pass `null` (engine does not yet have trigger context — see engine#231), and documents the intent in Javadoc.

**Tech Stack:** Java, Maven multi-module, JUnit 5, AssertJ. No containers needed for these tests.
